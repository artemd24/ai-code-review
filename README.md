# AI Code Review

CLI-утилита: забирает diff (локально / GitLab MR / GitHub PR), отправляет его в LLM через OpenRouter, публикует комментарии и summary.

## Задачи из бэклога (что сделано и зачем)

### 1. Конфиг-файл для запуска CLI

**Смысл:** не дублировать длинные флаги и секреты в командной строке; хранить профили (локальный review, CI и т.д.).

**Реализация:** файл TOML, путь задаётся через `--config`. Значения из файла подставляются как значения по умолчанию; явные аргументы CLI их переопределяют. Секреты можно вынести в переменные окружения строкой вида `api_key = "env:OPENROUTER_API_KEY"`. Пример: [`code_review.example.toml`](code_review.example.toml).

### 2. Переполнение контекста и «умное» разбиение diff

**Смысл:** большой MR не помещается в одно окно модели; нужно резать diff на батчи с запасом под системный промпт и ответ, без потери границ файлов по возможности.

**Реализация:**

- Для каждой модели в [`SupportedModel`](code_review/lib/supperted_models.py) задано приблизительное `context_window_tokens`.
- Лимит токенов на **текст diff** в одном запросе: `default_max_diff_tokens()` = окно контекста минус резерв под промпт и ответ, либо явный `--max-diff-tokens` / ключ `max_diff_tokens` в конфиге.
- Модуль [`code_review/lib/diff_splitter.py`](code_review/lib/diff_splitter.py): грубая оценка токенов как `len(text) // 4`, разбиение по границам `--- ` (файлы unified diff), упаковка частей в батчи; при необходимости — по строкам и длинным строкам.
- [`ReviewOrchestrator`](code_review/review_orchestrator.py) вызывает LLM по одному разу на батч; комментарии объединяются, summary склеивается с заголовками «Часть i / n». В промпт для многочастевого случая добавляется пометка ([`PromptBuilder.get_prompt`](code_review/lib/prompt_builder.py)), что виден только фрагмент diff.

**Заметки по исследованию (Codex / OpenCode и др.):** у разных продуктов различаются размер контекста, политика слайдинга и разбиения на чанки; на практике важно явно резервировать место под инструкции и вывод и не полагаться на «ровно» заявленное окно — отсюда консервативный резерв в коде.

### 3. Тесты: моки адаптеров, сервисов, контекст

**Смысл:** быстрые изолированные проверки без сети и без реальных ключей; отдельно проверить разбиение diff и сценарий оркестратора.

**Реализация:**

- Адаптеры: [`tests/adapters/`](tests/adapters/) — `requests` / `Repo` патчатся через `unittest.mock`.
- Конфиг: [`tests/test_config_loader.py`](tests/test_config_loader.py).
- Разбиение diff и лимиты: [`tests/lib/test_diff_splitter.py`](tests/lib/test_diff_splitter.py).
- Оркестратор с моками адаптера и LLM: [`tests/test_review_orchestrator.py`](tests/test_review_orchestrator.py).

Запуск: `python3 -m pytest tests/ -q` (зависимости в [`requirements.txt`](requirements.txt)).

### 4. Code Review в Codex / Copilot / Cursor

**Смысл:** понять, как ведущие IDE и CLI позиционируют ИИ–review относительно полного контекста репозитория и диффа.

**Кратко (обзор, не часть кода):**

| Продукт | Типичный контекст | Поведение review |
|--------|-------------------|------------------|
| **GitHub Copilot (IDE)** | Текущий файл, иногда связанные, настройки чата | Фокус на открытом коде; для «всего PR» обычно нужны отдельные flow (Copilot Chat / интеграции). |
| **Cursor** | Выбранные файлы, `@`-контекст, индексация репо | Гибкий контекст в чате; для полного MR по-прежнему важно явно подмешивать diff или файлы. |
| **OpenAI Codex / CLI-агенты** | Зависит от модели и оболочки; часто батчи и сжатие истории | Сходная идея с этим проектом: не превышать окно, дробить работу. |

Вывод для этого репозитория: явное разбиение большого diff и настраиваемый лимит токенов приближают поведение к тому, что делают «умные» CLI, не полагаясь на непрозрачный слайдинг внутри одного запроса.

## Запуск

```bash
python3 main.py --adapter local --model qwen3 --level FULL \
  --api-key "$OPENROUTER_API_KEY" --source feature --target main
```

С конфигом:

```bash
python3 main.py --config code_review.example.toml
```

Обязательные параметры (`adapter`, `model`, `api-key`) должны быть заданы в CLI или в конфиге.
